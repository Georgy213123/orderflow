# 05. Тестирование

## Пирамида

```
            e2e Playwright          4 сценария × десктоп и телефон
          ─────────────────
        integration pytest          HTTP + PostgreSQL, сквозной путь заявки
      ───────────────────────
    unit pytest + Vitest            разбор, поля, конструкция, смета, деньги, статусы, UI
  ───────────────────────────────
```

Почему так. Ценность кейса — в предметных правилах: единицы в тексте, проём шкафа,
округление сметы, переходы статусов. Это чистые функции в `app/domain`, их дёшево
и быстро проверять unit-тестами на граничных случаях. Интеграционные тесты проверяют
склейку: миграции, сохранение снимка сметы, коды ошибок 404/409/422, историю
переходов. e2e проверяет то, что видит менеджер: подсветку источника, блокировку
кнопок, итог на экране, работу формы на телефоне.

## Что проверяет каждый слой

| Слой | Где | Что проверяет |
|---|---|---|
| unit, бэкенд | `backend/tests/unit/` | разбор текста и единиц; правило подтверждения поля; спецификация и инварианты; смета, округление, неполный итог, даты цен; деньги в копейках; таблица переходов; заглушки адаптеров; совпадение `openapi.yaml` с кодом |
| integration | `backend/tests/integration/` | параллельные операции над одной заявкой (блокировка строки); миграции `downgrade base` → `upgrade head` на реальном PostgreSQL; весь путь через HTTP; отказ на пропуск шага; 422 на неверную конструкцию; запрет отправки неполной сметы; удаление сметы при правке конструкции |
| unit, фронт | `frontend/src/**/*.test.ts(x)` | переключение заявок и запоздавшие ответы; форматирование копеек и количеств из строки; строка поля: подсветка, подтверждение, правка; шаги статуса; подстановка параметров шкафа из заявки |
| e2e | `e2e/tests/` | US-01…US-05 в браузере: текст → подсветка → подтверждение и правка → конструкция с ошибкой и без → спецификация → итог 12 331,96 ₽ → «смета готова»; неполная смета; мобильная форма без горизонтальной прокрутки |

Один и тот же ожидаемый итог шкафа 1200 × 2100 × 600 (4 полки, 2 двери, плита 16 мм)
проверяется на трёх уровнях: `test_estimate.py::EXPECTED_TOTAL_KOP`, интеграционный
`test_us03_us04_us05_full_flow` и e2e `полный путь` (NFR-02).

## Отчёт прогона

Последний прогон 2026-11-03, после исправлений по ревью (v0.3.1), локально: macOS, Python 3.12, Node 24,
PostgreSQL 16 (Homebrew) на порту 55301, Chromium из Playwright 1.64.

| Команда | Результат |
|---|---|
| `make lint` | ruff: All checks passed, 40 files already formatted; mypy strict: no issues in 39 files; eslint, tsc, prettier — без замечаний |
| `make test` — pytest | **82 passed за 4,97 с** (67 unit, 15 integration) |
| `make test` — покрытие `app/` | **97 %** (957 строк, 26 не покрыто); `domain/estimate`, `fields`, `money`, `status` — 100 %, `design` — 93 %, `parser` — 99 % |
| `make test` — Vitest | **16 passed** в 5 файлах за 1,34 с |
| `make e2e` | **7 passed, 1 skipped за 11,8 с** (4 сценария × 2 вьюпорта; мобильный сценарий на десктопе пропускается намеренно) |
| `make audit` | pip-audit: No known vulnerabilities found; npm audit фронта: 0 high, 12 moderate (цепочка `minimatch` внутри ESLint, только инструменты разработки, исправление требует ломающего обновления typescript-eslint); e2e: 0 |
| проверка багов | BUG-01…05: 5 из 5 тестов падают при подмене исходного кода; BUG-06…10 и остальные находки ревью: тест падал до исправления (см. 06-bugs.md) |

Не проверено: `make up` — Docker на машине сборки не установлен, `docker-compose.yml`
проверен только как валидный YAML.
