# ADR-0002. Внешние сервисы за адаптерами

Статус: принято, 2026-10-21.

**Контекст.** Разбор текста моделью, отправка сметы, выгрузка в учётную систему. Демо должно
работать без сети и ключей. Модель ошибается так же, как правила.

**Варианты.** 1) Вызывать модель прямо из обработчика. 2) Интерфейс `RequestParser`:
правила по умолчанию, адаптер модели с откатом на правила, выбор переменной окружения.
3) Только правила.

**Решение.** Вариант 2; так же `ClientNotifier` (заглушка `LogNotifier`) и
`AccountingExporter`. Адаптер модели возвращает тот же тип, что и правила, —
`FieldKey → ParsedField`. Найденное моделью тоже приходит неподтверждённым и без человека
не попадает в смету.

**Последствия.**
- Подключение модели — один класс и переменные `REQUEST_PARSER`, `LLM_API_URL`, `LLM_API_KEY`.
- Правила знают только типовые формулировки, остальное менеджер вводит руками.
- Адаптер не реализован (TODO в `app/domain/parser.py`): нужны таймаут, строгая схема
  ответа, откат на правила.
