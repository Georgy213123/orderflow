# ADR-0001. Стек: FastAPI, PostgreSQL, React

- Статус: принято
- Дата: 2026-10-20

## Контекст и проблема

Нужен стек для демо «заявка → смета», который покажет проектирование API, работу с
реляционными данными и интерфейс. Данные строго структурированы: заявки, поля,
детали, строки сметы со связями. Деньги и количества требуют точной арифметики.

## Факторы решения

- точные типы для денег и количеств на уровне базы;
- контракт API генерируется из кода, чтобы его можно было сверять тестом;
- одинаковый стек с другими кейсами витрины, единый Makefile и CI;
- быстрые unit-тесты предметной логики без базы.

## Рассмотренные варианты

1. FastAPI + SQLAlchemy 2 + PostgreSQL 16, фронт React + TypeScript (Vite).
2. Django + DRF + PostgreSQL, шаблоны или тот же React.
3. Node.js (NestJS) + PostgreSQL, React.

## Решение

Вариант 1. FastAPI отдаёт OpenAPI из pydantic-схем, контракт выгружается в файл и
сверяется тестом. PostgreSQL даёт `NUMERIC`, `BIGINT`, `JSONB` и `CHECK`-ограничения
на статусы и виды материалов. SQLAlchemy 2 с типизированными моделями проходит mypy strict.

### Последствия

- Хорошо: предметная логика — чистый Python с `Decimal`, тестируется без базы.
- Хорошо: схема меняется только миграциями Alembic, откат проверяется в тестах.
- Плохо: админки «из коробки», как в Django, нет. Справочник материалов в демо
  заполняется начальными данными, экран справочника отложен.
- Плохо: два языка в проекте (Python и TypeScript), типы ответа API на фронте
  описаны вручную. Генерация клиента по openapi.yaml — кандидат на следующую версию.
