# ADR-0004. Статусы заявки — машина состояний на сервере

Статус: принято, 2026-10-23.

**Контекст.** Статусы: новая, разобрана, конструкция готова, смета готова, отправлена
клиенту. Если статус ставит кто угодно, появятся сметы без конструкции и неполные итоги
у клиента.

**Варианты.** 1) `PATCH status` из клиента API. 2) Таблица переходов на сервере, статус
меняется как следствие действия; явный запрос только для «разобрана» и «отправлена
клиенту». 3) Библиотека конечных автоматов.

**Решение.** Вариант 2. `app/domain/status.py` хранит `ALLOWED`, `check_transition` бросает
`TransitionError`. Сервис добавляет условия: для «разобрана» поля подтверждены, для отправки
смета полная. Нарушение — 409 с `message` и `problems`, переходы пишутся в `status_changes`.
Обратный переход один: смета готова → конструкция готова при правке шкафа, смета удаляется.

**Последствия.**
- Кнопки на фронте только отражают ответ сервера.
- Статусы производства потребуют отдельной сущности заказа.
